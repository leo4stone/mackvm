# MacKVM 屏幕相邻规则：需求定稿（2026-10-20 讨论结论；2026-10-21 补第七节跨出判定与光标隐藏）

界面以 Pencil 设计稿为准（稿子不在仓库里），
节点 R9pul（06 设备连接 / 按规则拖动屏幕）、sxiFo（06A 添加规则）；导出图在 `<mackvm>/design/v5/`。
本文记录讨论中定下、设计稿表达不全的规则。

## 一、基本模型

1. 两台 Mac 各自可接任意多块显示器；两台之间的显示器可以两两单独配一条「相邻规则」。
2. 屏幕尺寸一律按物理尺寸（毫米，取自 `CGDisplayScreenSize`）计算，不看分辨率和点数。
   读不到或明显不合理时按分辨率估算，界面标明「尺寸为估算」。
3. 一条规则 = 本机某块屏的某条边 ↔ 对方某块屏的某条边 + 沿边错开的位置（毫米）。
4. 光标只在两条边实际挨着的那一段能跨过去，双向都可以；落点按毫米位置一一对应，不拉伸。
   没挨着的部分保持原样（通往自家另一块屏，或是屏幕尽头）。
5. 同一台 Mac 自己的几块屏怎么排、怎么相通，由 macOS 管理（按点），这里只展示不修改。

## 二、约束

| 约束 | 结论 |
|---|---|
| 同样两块屏 | 只能有一条规则（否则规则冲突） |
| 规则盖住自家两块屏原本相通的一段 | 允许，**规则优先**：那一段跨到另一台。拖到这里给一句提醒，不阻止 |
| 同一条边被多条规则使用 | 允许，但各规则在这条边上的段落不能重叠；重叠时不能放下，并说明和哪条规则重叠 |
| 挨着的长度 | 至少 10 毫米 |
| 只能选外侧的边 | 已取消 |

典型场景：U2720QM 右边上半段挨着自家 P2319H（照常在两块 DELL 之间走），
下半段空出来、挨着 MacBook（设规则，跨到 MacBook）。

## 三、操作流程

- 添加规则：弹窗里两台设备各一组单选，各选一块显示器，不选边；已有规则的两块屏不能再加（提示「已有这条规则」）。
- 新规则的初始位置：优先放在对方那台已有规则所在方向的边上，不能用就按右、左、下、上找第一条能用的边；两边中点对齐。
- 在主预览里拖动对方屏幕：拖到另一侧可换相邻边，靠近有效边时吸附，再沿边调整错开。
- 预览只显示当前规则的两块屏，按物理尺寸等比例画；放不下时整体自动缩小，比例不变。
- 规则用下拉框切换；可删除任意规则，删最后一条前确认（删后跨不到另一台）。
- 修改立即生效，两台同步。

## 四、显示器命名

- 同一台 Mac 有多块屏时，一律加位置后缀，按 macOS 系统排列决定：左/右、上/下、左/中/右，复杂摆法组合（如「左上」）。
  例：「DELL U2720QM（左）」「DELL P2319H（右）」。只有一块屏的 Mac 不加后缀。
- 规则名：本机显示器标签 + 对方显示器标签，如「DELL P2319H（右）+ 内建屏幕」。
- 后缀随系统排列变化；程序内部用显示器序列号识别屏幕。
- 配色：本机浅蓝底蓝边蓝字，对方白底灰边灰字，不随输入角色切换。

## 五、默认规则

- 配对完成时自动添加一条：**主控电脑最右侧显示器的右边 ↔ 被控电脑最左侧显示器的左边，中点对齐**。
- 「最右侧」= 右边缘在系统排列中最靠右；并列时选主屏，主屏不在其中则选最上面那块。「最左侧」同理。
- 只在配对完成、还没有任何规则时生成一次；之后规则删光不会自动补回。
- 对调角色后规则不变（规则绑定具体屏幕，与角色无关）。

## 六、其他行为

- 按住鼠标键时规则不触发；被规则占用的自家相通段，按住鼠标键经过时恢复原样（拖窗口照常能在自家两块屏之间拖）。
- 镜像显示的一组屏算作一块。
- 光标快速甩过短段时，按前后两点连线是否穿过规则段落来判定，避免漏判。
- 显示器拔出：相关规则保留并标明暂时失效，插回后自动恢复。
- 对方离线：仍可查看和编辑，标明使用上次连接信息、待同步，重连后同步。
- 没有可用规则：页面提示「光标现在跨不到另一台」，并给出紧急收回热键 Ctrl+Option+Cmd+L。
- 以上反馈都放在当前页面，不另开状态页，不因日常断线主动弹窗。

## 七、跨出判定与主控方光标隐藏（2026-10-21 定案，15.8 起生效）

这一节记录的是实现时踩到的 macOS 系统行为和最终做法，和界面无关。

### 问题

主控方（键鼠所在的 Mac）在光标跨到另一台之后，要把本机光标藏起来并停在主屏中心。
实测反复出现「隐藏调用返回成功，光标却画在主屏中心」，而且慢推必现、快推没事；程序坞在跨出的那块屏上时更容易出现。

### 原因（有依据）

- Apple DTS 工程师在开发者论坛（thread 756199）的回答：窗口服务器里有一段专门逻辑，只要程序坞会成为「活动目标」，
  就让程序坞保持对光标的控制，这会挡掉后台进程用来隐藏光标的 SetsCursorInBackground。这类例外没有正式文档。
- esp-hid 项目（PR #27）实测：从光标进入程序坞区域的第一个事件起，到有一个事件落在区域外为止，窗口服务器会无视该进程的
  CGDisplayHideCursor 和 warp；程序坞只看送达的事件，warp 结束不了它的跟踪。
- 本机截图实验（带光标的系统截图）证实：光标压在屏幕底边、或进过程序坞条之后，隐藏加 warp 不生效；
  只补发一个送达的事件不够，补发事件再「显示 + 隐藏」重申一次才藏住。
- 慢推必现的原因：慢推时事件位移是亚像素，光标会先在最底下那一行像素停一两个放行给系统的事件，程序坞就开始跟踪；
  快推时第一个碰边的事件就被截获通道吞掉，系统从没见过光标压在边上。

### 做法

1. **跨出触发线是屏幕真正的边**（最靠边的那一行像素：下边 maxY−1、右边 maxX−1、上边 minY、左边 minX），
   程序坞在这条边上也一样，推过程序坞到屏幕边才切，程序坞照常能用。
2. **慢推也能触发**：不足 1 点的位移按 1 点算；光标已经停在边上那一行、这一下没有位移的事件也算往外推。
3. **跨出点和回来的落点放在可用区域里**（扣掉程序坞条），回来时不落进程序坞。
4. **切到远端的顺序**：设 SetsCursorInBackground → CGDisplayHideCursor（主屏）→ warp 到主屏中心 →
   从回调外发一个带注入标记的 mouseMoved 到主屏中心（截获通道放行，程序坞看到光标离开就交出控制权）→
   0.1 秒后 CGDisplayShowCursor + CGDisplayHideCursor 重申一次（计数不变）。没被跟踪时这两步无害。
5. **远端期间不去挪藏着的光标**。藏着的光标一直停在主屏中心；事件里的位置只是 HID 自己的累加器，会被屏幕边夹住，
   碰到边无害。远端期间的 warp 改不动这个累加器，挪了也白挪。发给对方的位移取事件的位移字段（mouseEventDeltaX/Y），
   切到远端那次 warp 的跳变按「位移字段模长超过 150 且位置在主屏中心 200 点内」剔除。

### 已否定的做法（别再试）

- 触发线提前到程序坞上沿（15.6）：能避开问题，但程序坞在规则边上时那一截程序坞够不着。
- 远端期间靠边时把光标挪回主屏中心（15.1～15.4）：warp 改不动 HID 累加器，几百次挪回没有一次落地；夹在隐藏/显示之间也一样。
- CGAssociateMouseAndMouseCursorPosition(false)：在这个后台进程里不生效。
- 靠程序日志判断光标可见与否：隐藏调用返回 0 不代表画没画。要判断只能用带光标的系统截图
  （`screencapture -C -x -R x,y,w,h`）配合日志里「切到远端」的时间点。

## 八、07 光标特效页文案

设计稿仍写「鼠标离开 / 进入这张卡片时」「从左向右移入卡片体验波纹」，与现行规则（越过中线才触发、双向）不符；
沿用程序里已改的说法：「光标离开 / 进入一块屏幕时……」「越过分界线即可体验波纹」。
